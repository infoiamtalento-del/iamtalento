# STAGE 11 — Security hardening, observability, performance, compliance

**Goal:** production readiness. Nothing new in features; everything about making it safe, fast, observable and legal.

## Tasks
1. **Automated RLS/function audit** as a vitest suite `rls_audit.test.ts` that fails CI when: a public table has RLS off; a policy uses `using (true)` for a non-public table; any `SECURITY DEFINER` function lacks `set search_path`; `anon` can execute anything not in the allow-list file `docs/backend/ANON_ALLOWLIST.txt`; any table named like money/ledger/score/role has a client write policy; every FK has an index.
2. **Edge functions**: strict CORS allow-list, `verify_jwt=true` everywhere except the HMAC webhooks (`payments?action=webhook`, `email-events`), request size limits, schema validation on every body, per-user rate limit through `rate_limit_hit`, uniform error shape, `x-request-id`, no stack traces, timeouts on outbound calls, retry only idempotent operations.
3. **Frontend headers** in `vercel.json`: `Content-Security-Policy` (self + Supabase + Razorpay + Turnstile + the CDN hosts used by the app; test the video and fonts), `Strict-Transport-Security`, `X-Content-Type-Options`, `Referrer-Policy`, `Permissions-Policy` (camera/mic only on assessment routes), `frame-ancestors 'none'`. Ensure no `dangerouslySetInnerHTML` with untrusted data (grep and fix; sanitize with DOMPurify where required).
4. **Encryption of sensitive columns**: `pan_number`, any government-id reference, `signing_secret` in `tenant_api_keys_webhooks`, webhook secrets. Use Supabase Vault/pgsodium or app-level envelope encryption through definer functions; migrate existing plaintext; rotate secrets. API keys stored only as hash + prefix (verify the existing design, implement `create_api_key` showing the secret once, `revoke_api_key`).
5. **Seed data**: move `…100500_seed_platform_data` content out of the migration chain into `supabase/seed.sql` and a guarded `supabase/seed_demo.sql`; production migration chain keeps only reference data (core assessment catalog, plans, notification kinds, permissions). Flag demo rows `is_demo`.
6. **Performance**: seed 1M profiles / 200k jobs / 2M applications in a scratch DB; `EXPLAIN (ANALYZE, BUFFERS)` for `search_jobs`, `search_candidates*`, `list_applications`, `employer_dashboard`, `recommend_jobs`, notification list. Add missing indexes (composite, partial on `status='active'`), keep p95 < 150 ms for list RPCs, tune HNSW (`m`, `ef_construction`, `ef_search`), materialized views refreshed by cron for dashboards/percentiles, connection pooling through the transaction pooler, `statement_timeout` per role (`authenticated` 8 s).
7. **Observability**: Sentry in web and functions (scrub PII), structured JSON logs, `/health` function (db ping + queue lag), Postgres alerts (replication, bloat, slow queries via `pg_stat_statements`), outbox/webhook dead-letter dashboards (SQL views), uptime check, status runbook `docs/backend/RUNBOOK.md`.
8. **Backups and environments**: PITR/backups on, separate `staging` project, migration promotion process (`supabase db push` staging → prod after CI), rollback notes per migration, secrets rotation calendar.
9. **Compliance pack** (DPDP Act 2023): consent screens versions tracked (Stage 1), data inventory `docs/compliance/DATA_MAP.md`, retention schedule implemented by cron (applications 24 mo, proctoring media 90 d, auth events 12 mo, support 36 mo, logs 12 mo), grievance officer and DPO contact page placeholder, breach response runbook, processor list (Supabase, Razorpay, email/SMS, AI provider) and cross-border note, children's data guard (age ≥ 18 confirmation at signup).
10. **AI safety hooks** (shared by A1/Parse-resume): central `ai_usage` table (user, tenant, feature, tokens, cost, at), per-feature quotas, output schema validation, prompt-injection policy doc, no secrets or other users' data in prompts, human-review flags for decisions affecting candidates.

## Acceptance
`rls_audit` green in CI; CSP report-only for 1 week then enforced; p95 targets documented with measurements; backup restore drill executed once on staging and written up.
